# skewlens

**Find the columns that will break your joins.** `skewlens` profiles a JSONL
dataset in one parallel pass and ranks every column by the three things that
actually hurt: a hot key, a wall of nulls, and a cardinality that does not fit
in memory.

```console
$ skewlens run --rows 1000000 --workdir demo
skewlens 0.1.0  1,000,000 rows  112.3 MB  0.8409 s  133.5 MB/s  4 worker(s)
 #  column           score  grade     top share   nulls
 1  user_id           0.55  critical      13.9%    0.0%
 2  referrer          0.27  medium         1.3%   84.9%
 3  session_id        0.12  low            0.0%    0.0%
 4  country           0.09  low            2.5%    0.0%
 5  amount            0.00  low            0.0%    0.0%
report: demo/report.md
```

## Why a second profiler

`pandas.describe()` and `SELECT count(distinct x)` both answer "what is in this
column" by materialising it. At a few hundred million rows that stops being a
question you can ask casually, and the answer you usually need is smaller than
the data: *is one key carrying the join, and will the group-by fit?*

`skewlens` answers that question with sketches that never grow with row count:

- **HyperLogLog** (2^14 registers, ~0.8% standard error) for cardinality, with an
  exact set kept while a column stays under 2,000 distinct values.
- **Count-Min sketch** (4,096 × 4) plus Space-Saving candidates for frequency.
- **Chan's parallel formula** for numeric mean and standard deviation.

The report ranks columns by a documented score, and it can check itself against
a generator's exact ground truth.

## Install and run

```bash
python -m pip install -e .
skewlens run --rows 1000000 --workdir demo --workers 4
```

Requirements: Python 3.11+, Node 22.6+ (the scanner runs TypeScript directly
through `--experimental-strip-types`, so there is no build step and no
`node_modules`).

Four commands are available:

| Command | Purpose |
| --- | --- |
| `skewlens synth` | Write a synthetic JSONL dataset plus exact ground truth. |
| `skewlens scan` | Profile a JSONL file and emit the raw profile as JSON. |
| `skewlens report` | Rank risks and write Markdown/JSON; optionally verify against truth. |
| `skewlens run` | All three in one step. |

Point it at your own data with `skewlens scan --input events.jsonl --workers 8`
followed by `skewlens report --profile profile.json`.

## How the score works

Each component is normalised to 0..1 and saturates at a stated point, so the
number is arguable instead of mysterious:

| Component | Weight | Saturates at |
| --- | --- | --- |
| skew | 0.55 | one value holding 10% of rows |
| nulls | 0.25 | a 50% null rate |
| cardinality | 0.12 | a distinct ratio of 1.0 (skipped for numeric columns) |
| drift | 0.08 | any coverage gap or mixed non-null types |

Grades: `critical` ≥ 0.55, `high` ≥ 0.33, `medium` ≥ 0.14, otherwise `low`.
Skew carries the largest weight because a hot join key is the failure this tool
exists to catch; a unique identifier is normal, so cardinality alone cannot push
a column past `medium`.

## Measured results

One Windows 11 machine, 12 logical cores, Python 3.13.14, Node 22.22.2, warm
file cache. The dataset is 1,000,000 rows and 112.3 MB of JSONL generated by
`skewlens synth --seed 11`.

| Workers | Wall time | Throughput |
| --- | --- | --- |
| 1 | 2.23 s | 50.3 MB/s |
| 4 | 0.82 s | 137.3 MB/s |
| 8 | 0.67 s | 166.9 MB/s |

Memory does not follow the row count. With a single worker, 100,000 rows used
113 MB RSS and 34 MB live heap; 1,000,000 rows used 147 MB RSS and 20 MB live
heap. The retained data is the sketch, not the rows, so ten times the input
produced no growth in live heap.

Accuracy against the generator's exact counts, from the same run:

| Column | Exact distinct | Estimated | Error |
| --- | --- | --- | --- |
| `country` | 40 | 40 | 0.00% (exact) |
| `referrer` | 12 | 12 | 0.00% (exact) |
| `session_id` | 1,000,000 | 1,013,816 | 1.38% (HLL) |
| `user_id` | 42,392 | 43,143 | 1.77% (HLL) |

The top value matched ground truth for every column where the generator recorded
one, including the 13.9% hot key.

## Limits

- **JSONL only.** CSV, Parquet, and Avro are not read; convert first. Nested
  objects are counted as an `object` type and skipped by the sketches.
- **Estimates, not counts.** Cardinality is within roughly 1% at these sizes;
  frequency error is bounded by rows ÷ 4,096. Both are reported with the method
  that produced them.
- **Candidate sampling.** For high-cardinality columns, new values are admitted
  to the candidate set at 1/64. The Count-Min sketch still holds the real
  counts, so a value missing from `top` is a rare value, not a miscount.
- **Single file, single machine.** Ranges are byte offsets inside one file; there
  is no distributed mode.
